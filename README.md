# 口译交接时间轴对齐工具（Interpreter Handoff Aligner）

一场多语发布会结束后，两名口译员各自记录了交接附近听到的事件。漏记、补记与
时间偏移使组长无法直接对照双方笔记。本工具接收两组 JSON 笔记，使用**动态规划**
求出**全局最优且唯一**的对齐时间轴，并在页面上逐行展示配对、两类空缺、单步
代价、累计代价与总代价，支持逐步复算。复盘时组长还可把少量**人工确认的配对**
标记为**锚点**：系统沿用原始两组输入，以锚点切分区间后运行同一套 DP，页面明确
区分「人工锚点」行与「算法生成」行。

复盘较长发布会时，组长还可勾选**「比较备选对齐」**：后端在**同一代价与平局规则**
下额外求出**严格次优的完整路径**，返回次优总代价、与最优路径的成本差，以及双方
**首次分歧**所涉及的笔记索引；页面仍以最优时间轴为主体，只在分歧行旁展开备选配对
与成本差。锚点约束或空输入使合法路径唯一时，页面明确提示没有备选路径，同时正常
展示最优结果。该开关缺省关闭，旧请求的响应与以往字节级一致。

跨语言复盘时，同一专名常被两名口译员写成**不同译法**。组长可在提交前先录入本次
复盘**认可的术语对应**（页面可随时新增、删除左右译法对）：后端只在**配对步骤**把
与某条术语对**完全命中**的两个文本视为同义，**免除文本不一致的 3000 罚分**，只保留
时间差；时间差、留空代价、锚点约束、平局顺序与备选路径排序全部沿用现有实现。请求
增加可选的 `term_pairs` 数组，响应中命中的配对行标记所用术语对（页面展示「术语
等价」来源），未命中行保持原有来源展示；不传或传空数组时，请求计算与响应结构与
当前版本完全一致。

- 后端：Python 3.12 · FastAPI · 纯标准库实现的 DP（无任何外部匹配库）
- 前端：TypeScript · React 18 · Vite
- 测试：pytest（算法/校验/API）· Vitest（前端逻辑与组件）· Playwright（真实前后端联调）
- 部署：Docker Compose（web + api + 一次性 `verify` 验收服务）

## 1. 输入格式与示例

页面左右两个文本框各接收一个 **JSON 数组**；请求体形如
`{"left": [...], "right": [...]}`。每项**仅含**两个字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `time` | 整数 | 毫秒时间戳；组内**严格递增、不可重复** |
| `text` | 非空字符串 | 听到的内容 |

单组最多 **200** 项。结构错误、超限、重复/非递增时间、多余字段都只会产生
**一次**明确失败，响应（与页面高亮）指向首个错误路径，如 `left[2].time`，
且原始输入原样保留。

> **超大毫秒整数**：`time` 按任意精度整数处理。前端手写的 JSON 解析器把
> 整数数字字面量保留为 `BigInt`，并将两个文本框里的数组**原始文本**直接
> 发给后端（不经过 `JSON.parse`/`JSON.stringify` 重序列化），后端 Python
> 原生支持任意精度整数。因此即使相邻时间超过 `Number.MAX_SAFE_INTEGER`
> （2⁵³−1，例如 `9007199254740993` 与 `9007199254740995`），也不会因
> double 舍入而被误报为重复；真正相等的超大整数仍会被准确拦截。

### 输入示例

```json
{
  "left": [
    {"time": 0, "text": "各位媒体朋友下午好"},
    {"time": 4200, "text": "新产品将于下月上市"},
    {"time": 9000, "text": "感谢各位的提问"}
  ],
  "right": [
    {"time": 150, "text": "各位媒体朋友下午好"},
    {"time": 4100, "text": "新产品将于下月上市"},
    {"time": 12000, "text": "交接后的补充记录"}
  ]
}
```

### 输出示例（节选）

```json
{
  "steps": [
    {"action": "match", "left": {"time": 0, "text": "各位媒体朋友下午好"},
     "right": {"time": 150, "text": "各位媒体朋友下午好"}, "cost": 150, "cumulative_cost": 150},
    {"action": "match", "left": {"time": 4200, "text": "新产品将于下月上市"},
     "right": {"time": 4100, "text": "新产品将于下月上市"}, "cost": 100, "cumulative_cost": 250},
    {"action": "right_gap", "left": {"time": 9000, "text": "感谢各位的提问"},
     "right": null, "cost": 2000, "cumulative_cost": 2250},
    {"action": "left_gap", "left": null,
     "right": {"time": 12000, "text": "交接后的补充记录"}, "cost": 2000, "cumulative_cost": 4250}
  ],
  "total_cost": 4250,
  "counts": {"match": 2, "left_gap": 1, "right_gap": 1},
  "costs": {"gap": 2000, "mismatch_penalty": 3000}
}
```

三种动作（动作名表示**该行哪一侧留空**，非空的另一侧携带该条笔记）：

- `match`：左右各一项配对；
- `left_gap`：**左侧留空**，行内只有右侧记录（左侧漏记）；
- `right_gap`：**右侧留空**，行内只有左侧记录（右侧漏记）。

因此整组笔记只在一侧时，每一行都会正确地标出实际留空的另一侧：
只有 `left` 输入时动作为 `right_gap`，只有 `right` 输入时为 `left_gap`。

## 2. 代价规则与唯一性

对 `(m+1) × (n+1)` 的 DP 矩阵求最短路：

| 动作 | 单步代价 |
| --- | --- |
| 配对，`text` **相同** | `|timeL − timeR|` |
| 配对，`text` **不同** | `|timeL − timeR| + 3000` |
| 任一侧单项留空 | `2000` |

**平局裁决（保证时间轴唯一）**：总成本最小优先；成本相同时依次偏好

1. 配对（match）
2. 左侧留空（left gap）
3. 右侧留空（right gap）

动作仍无法区分时，取前驱坐标 `(i, j)` 字典序较小者。回溯得到的步骤按
笔记顺序排列，每一步带 `cumulative_cost`，页面的「上一步 / 下一步」按钮
可据此逐步复算到最终总代价。

### 人工确认锚点（可选）

复盘时组长若已确认某几条左右笔记属于同一次发言，可在页面时间轴上方各点选
一条左右记录，把这对索引固定为**锚点**。请求体额外携带可选的 `anchors`
数组（0-based 索引）：

```json
"anchors": [{"left": 0, "right": 0}, {"left": 2, "right": 1}]
```

- 锚点把 DP 网格切分为若干独立区间；区间内仍运行**同一套动态规划与平局
  裁决**，锚点本身作为强制配对，按其**原有配对代价**（时间差，文本不同再
  +3000）计入总代价。因此「逐步复算」依旧逐行汇总到同一总代价。
- 含锚点的响应里，每个锚点行带 `"origin": "anchor"`，其余行带
  `"origin": "auto"`，并回显 `"anchors"`；页面用「人工锚点 / 算法生成」
  标签和描边清楚区分。
- 后端校验每个锚点：**索引必须存在**（不越界）、**不可复用**（同一索引
  不能配对两次）、且**左右两侧都严格递增**（不交叉）。任何违规只产生
  **一次**失败，路径指向首个确定错误的锚点，如 `anchors[2].left`；此时
  页面保留当前两组输入与已选标记，在对应锚点旁标错，且**不展示**可能被
  误认成有效的新时间轴。
- **向后兼容**：不传 `anchors`（或传空数组）的旧请求，其请求与响应与
  以往**完全一致**——不出现 `anchors`/`origin` 字段。取消全部锚点后重新
  提交即恢复原始无约束结果。

| 锚点违规 | 状态码 | path 示例 |
| --- | --- | --- |
| anchors 不是数组 | 422 | `anchors` |
| 锚点项不是对象 / 缺 left、right | 422 | `anchors[0]` / `anchors[0].left` |
| 索引越界（含空数组侧） | 422 | `anchors[0].right` |
| 索引被其他锚点复用 | 422 | `anchors[1].left` |
| 左右索引未同时递增（交叉） | 422 | `anchors[2].left` |

校验顺序固定为：先 `left`、`right` 两组笔记，再 `anchors`（按提交顺序
逐条），因此任何组合都只有首个错误被报告。

### 比较备选对齐（可选 `compare_alternative`）

勾选「比较备选对齐」后请求体额外携带可选布尔字段
`"compare_alternative": true`。后端在**同一代价矩阵与同一平局规则**下，
额外求出严格次优的**完整路径**（不是某个单步的替换），并在响应里追加
`alternative` 对象：

```json
"alternative": {
  "total_cost": 8000,
  "cost_diff": 1000,
  "first_divergence": {"left": 0, "right": 0},
  "steps": [ ... 与最优结果同构的逐行时间轴 ... ]
}
```

- `total_cost`：严格次优路径总代价；`cost_diff`：与最优总代价之差
  （**可以为 0**——存在同代价但配对不同的路径时，按平局规则确定二者顺序）。
- `first_divergence`：两条时间轴**首次分歧**所涉及的笔记索引（0-based）；
  备选在该行某侧留空时该侧为 `null`（例如尾端两种留空顺序之争会给出
  `{"left": null, "right": 2}`）。
- `steps`：备选完整路径，字段与最优 `steps` 完全一致（含各自的
  `cumulative_cost`）；含锚点时备选行同样带 `origin`，且锚点行与最优路径
  **完全相同**——锚点同时约束两条路径。

**确定性的次优顺序**：路径先按总代价排序；总代价相同时，比较两条路径
**最后一个不同步**（即回溯时重新汇合的那个网格点）的动作，仍按
「配对 > 左侧留空 > 右侧留空」裁决。算法用 **2-best DP** 实现：每个网格
点只保留最优的两个不同前缀（合并三个前驱各自的前两个前缀，共至多六个
候选），全局次优只会在某一个锚点区间内退化为该区间的次优前缀，时间复杂度
仍为 O(m·n)。

- 合法路径**唯一**时（典型为两侧皆空、只有单侧一条、或锚点把每个配对都
  固定）`alternative` 为 `null`，页面照常展示最优时间轴，并明确提示
  「不存在备选路径」。
- 结果页始终以最优时间轴为主体，仅在**首处分歧行**下方展开一行备选配对
  及其成本差；同代价备选会标注「按平局规则确定顺序」。
- **向后兼容**：`compare_alternative` 缺省或为 `false` 时不执行次优计算，
  请求与响应与以往**完全一致**（不出现 `alternative` 字段，旧请求响应
  字节级不变）。该字段不是布尔值时只产生一次失败，路径为
  `compare_alternative`；校验顺序仍为先两组笔记、再 `anchors`、最后该开关。

### 复盘认可的术语对应（可选 `term_pairs`）

跨语言复盘时同一专名常有两种译法。组长可在提交前于页面「复盘认可的术语对应」
面板录入或删除左右译法对；请求体额外携带可选的 `term_pairs` 数组：

```json
"term_pairs": [
  {"left_text": "人工智能", "right_text": "AI"}
]
```

每项**仅含**两个字段：非空字符串 `left_text` 与非空字符串 `right_text`。

- **仅完全命中才算同义**：只有某个**配对步骤**的左右文本与某条术语对
  **逐字完全一致**时，该配对才被视为同义——免除「文本不同」的 3000 罚分，
  单步代价只剩 `|timeL − timeR|`。子串、模糊匹配都不算；时间差、留空代价
  （2000）、锚点约束、平局裁决与备选路径排序**全部不变**。
- **逐字录入（含首尾空格）**：页面把组长录入的 `left_text`/`right_text`
  **逐字保留**，不做 trim 或任何改写；首尾空格也是术语文本的一部分，笔记
  文本必须连同空格完全一致才算命中。页面输入框仅在两侧都非空时允许添加
  （纯空格仍是合法术语）。「载入示例」与「清空为 []」会同时清空尚未添加的
  半成品草稿，重新从两个空白输入框开始。
- 含术语对的响应在原有字段后回显 `"term_pairs"`；命中的配对行额外带
  `"term_pair": {"left_text": ..., "right_text": ...}`，页面在「来源」列展示
  **「术语等价」**徽标并在「复算」列写出
  `术语等价「左 ≡ 右」：|tL − tR| = …（免除 3000）`。未命中的行保持原有
  来源展示（gap 行不受影响）。一条术语对的**左右两侧可以相同**：组长声明
  `(x, x)` 后，对齐同文笔记的配对行同样标记为该术语对的来源（同文本本来就
  无 3000 罚分，复算列不再写「免除 3000」）；未声明任何同文术语对时，普通
  相同文本行仍不打术语标记。备选路径在同一代价模型下求出，其命中行同样带
  `term_pair`；锚点强制配对命中术语对时也免除罚分。
- **同侧不可重复映射**：同一 `left_text`（或同一 `right_text`）只能出现
  一次；重复时只产生**一次**失败，路径指向首个冲突项，如
  `term_pairs[2].right_text`。一条术语对的左右两侧可以相同于另一条的对侧
  （仅按侧去重）。页面把冲突候选保留在列表中就地标红，保留两组笔记、锚点
  与全部术语输入，且**不替换**已有结果。
- **向后兼容**：不传 `term_pairs`（或传空数组）时请求计算与响应结构与以往
  **完全一致**——不出现 `term_pairs`/`term_pair` 字段，DP 代价与最优时间轴
  字节级不变。删除全部术语对后重新提交即恢复原始结果。

| 术语对违规 | 状态码 | path 示例 |
| --- | --- | --- |
| term_pairs 不是数组 | 422 | `term_pairs` |
| 术语项不是对象 / 缺字段 / 多余字段 | 422 | `term_pairs[0]` / `term_pairs[0].left_text` / `term_pairs[0].who` |
| 字段不是字符串或为空串 | 422 | `term_pairs[0].right_text` |
| 同侧术语重复映射 | 422 | `term_pairs[1].left_text` |

校验顺序固定为：先 `left`、`right` 两组笔记，再 `anchors`，然后 `term_pairs`
（按提交顺序逐条），最后 `compare_alternative`，因此任何组合都只有首个错误
被报告。

## 3. 快速启动（Docker Compose，推荐）

需要 Docker（含 Compose v2）。

```bash
docker compose up --build
# 打开 http://localhost:8080
```

宿主端口可用环境变量覆盖（容器内部端口固定为 web 80、api 8000）：

```bash
WEB_PORT=9090 API_PORT=9000 docker compose up --build
# 页面 http://localhost:9090 ，API 文档 http://localhost:9000/docs
```

也可以复制 `.env.example` 为 `.env` 后修改 `WEB_PORT` / `API_PORT`，
Compose 会自动读取。

### 一次性验收服务 verify

`verify` 服务对**正在运行的容器栈**做真实联调验收（健康检查、web→api
同源代理、黄金样例、三类代价、平局顺序、单次失败契约、结果幂等唯一性，
锚点的无锚点结果不变 / 合法锚点固定入列且区间最优 / 交叉单次报错 /
取消锚点恢复原结果，备选对齐的旧请求零新增字段 / 同代价与严格更贵
次优路径按确定顺序选出 / 首处分歧索引 / 唯一解空备选提示 / 锚点同时
约束两条路径 / 非布尔开关单次报错，以及术语对应的旧请求零新增字段 /
完全命中才免罚且逐步复算成立 / 子串等未命中仍计罚 / 锚点与备选路径
共同采用术语规则 / 同侧重复映射只报首个冲突一次 / 删除全部术语对恢复
原始结果），通过后退出码为 0：

```bash
docker compose up --build -d            # 先把 web/api 跑起来
docker compose run --rm verify          # 一次性验收，结束自动删除容器
docker compose down
```

## 4. 本地开发启动

### 后端（需要 Python 3.12；本地用 3.11 亦可运行测试）

```bash
cd backend
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
```

### 前端

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173 ，/api 自动代理到 127.0.0.1:8000
```

打开 http://localhost:5173 ，左右文本框已预填示例，点击「生成对齐」即可。

```bash

python -m pytest
```

## 6. HTTP 接口

- `GET /health` → `200 {"status": "ok"}`
- `POST /api/align`

成功返回 `200` 与对齐结果；任何输入问题都返回**一个**错误对象：

```json
{"error": "left[1].time 为 1，未严格递增（上一项时间为 1）。", "path": "left[1].time"}
```

| 场景 | 状态码 | path 示例 |
| --- | --- | --- |
| 请求体不是合法 JSON | 400 | `""` |
| 根不是对象 / 缺少 left、right | 422 | `""` / `left` |
| 某侧不是数组 | 422 | `right` |
| 超过 200 项（指向越界首项） | 422 | `left[200]` |
| time 缺失/非整数/重复/非递增 | 422 | `left[2].time` |
| text 缺失/非字符串/为空 | 422 | `right[0].text` |
| 存在 time、text 之外的字段 | 422 | `left[0].who` |
| anchors 非数组 / 项非对象 / 缺索引 | 422 | `anchors` / `anchors[0]` / `anchors[0].left` |
| 锚点索引越界、复用或交叉 | 422 | `anchors[2].left` |
| term_pairs 非数组 / 项非对象 / 缺字段 / 多余字段 | 422 | `term_pairs` / `term_pairs[0]` / `term_pairs[0].left_text` / `term_pairs[0].who` |
| 术语字段非字符串或为空 / 同侧重复映射 | 422 | `term_pairs[1].right_text` |
| `compare_alternative` 非布尔 | 422 | `compare_alternative` |

校验顺序固定为先 `left` 后 `right`、自上而下，两组笔记都通过后再按顺序
校验 `anchors`，然后校验 `term_pairs`，最后才检查 `compare_alternative`，
因此任何输入组合都只有**首个**错误被报告。成功响应在开启术语对应时于
原有字段后追加 `term_pairs` 回显与命中行的 `term_pair` 标记，开启比较时
再追加 `alternative`（唯一解为 `null`）；二者皆缺省时响应结构与以往完全一致。

## 8. 关于“无占位实现、无外部匹配库”

DP 矩阵、平局裁决与回溯全部为手写实现（`backend/app/alignment.py`），
未引入任何对齐/编辑距离/模糊匹配第三方库；术语同义仅做**逐字精确命中**的
手写集合判定，没有任何模糊匹配；前端的 JSON 源码定位解析器同样为手写递归
下降。所有层（算法对拍、组件交互、浏览器联调、容器内验收）均有自动化测试
覆盖。
